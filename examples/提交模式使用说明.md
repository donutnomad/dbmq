# DBMQ 消费者提交模式使用说明

DBMQ 支持两种偏移量提交模式：**手动提交**和**自动提交**，您可以根据业务需求选择合适的模式。

## 🎯 提交模式对比

| 特性 | 手动提交 | 自动提交 |
|------|---------|----------|
| **控制精度** | 高 - 精确控制何时提交 | 中 - 定时自动提交 |
| **数据一致性** | 高 - 消息处理完成后立即提交 | 中 - 可能存在重复处理 |
| **性能开销** | 高 - 每批消息都要提交 | 低 - 定时批量提交 |
| **使用复杂度** | 高 - 需要手动调用提交 | 低 - 自动处理 |
| **适用场景** | 金融、支付等要求精确性的场景 | 日志分析、监控等可容忍重复的场景 |

## 🔧 配置方式

### 手动提交模式

```go
consumer, err := pkg.NewConsumer(pkg.ConsumerConfig{
    DB:               dbClient,
    GroupID:          "my-consumer-group",
    EnableAutoCommit: false, // 禁用自动提交（默认值）
    // 其他配置...
})
```

在手动模式下，您有多种方式来提交偏移量：

#### 方式1：批量提交所有已拉取的消息
```go
for {
    messages, err := consumer.Poll(ctx, 1*time.Second)
    if err != nil {
        // 处理错误...
        continue
    }
    
    // 处理消息
    for _, msg := range messages {
        processMessage(msg)
    }
    
    // 批量提交所有已拉取消息的偏移量
    if len(messages) > 0 {
        if err := consumer.CommitSync(); err != nil {
            log.Printf("提交偏移量失败: %v", err)
        }
    }
}
```

#### 方式2：精确提交单个消息的偏移量
```go
for {
    messages, err := consumer.Poll(ctx, 1*time.Second)
    if err != nil {
        // 处理错误...
        continue
    }
    
    // 逐个处理和提交消息
    for _, msg := range messages {
        success := processMessage(msg)
        if success {
            // 只有处理成功才提交这个消息的偏移量
            if err := consumer.CommitMessage(msg); err != nil {
                log.Printf("提交消息 %d 偏移量失败: %v", msg.Offset, err)
            }
        }
    }
}
```

#### 方式3：批量指定偏移量提交
```go
offsetsToCommit := make(map[types.PartitionInfo]int64)

for {
    messages, err := consumer.Poll(ctx, 1*time.Second)
    if err != nil {
        // 处理错误...
        continue
    }
    
    // 处理消息并收集要提交的偏移量
    for _, msg := range messages {
        success := processMessage(msg)
        if success {
            partition := types.PartitionInfo{
                Topic:     msg.Topic,
                Partition: msg.Partition,
            }
            offsetsToCommit[partition] = msg.Offset
        }
    }
    
    // 批量提交指定的偏移量
    if len(offsetsToCommit) > 0 {
        if err := consumer.CommitOffsets(offsetsToCommit); err != nil {
            log.Printf("批量提交偏移量失败: %v", err)
        }
        // 清空已提交的偏移量
        offsetsToCommit = make(map[types.PartitionInfo]int64)
    }
}
```

### 自动提交模式

```go
consumer, err := pkg.NewConsumer(pkg.ConsumerConfig{
    DB:                 dbClient,
    GroupID:            "my-consumer-group",
    EnableAutoCommit:   true,            // 启用自动提交
    AutoCommitInterval: 5 * time.Second, // 每5秒自动提交一次
    // 其他配置...
})
```

在自动模式下，您无需手动调用提交方法：

```go
for {
    messages, err := consumer.Poll(ctx, 1*time.Second)
    if err != nil {
        // 处理错误...
        continue
    }
    
    // 只需要处理消息，偏移量会自动提交
    for _, msg := range messages {
        processMessage(msg)
    }
    // 不需要手动提交！
}
```

## 📝 配置参数说明

### EnableAutoCommit
- **类型**: `bool`
- **默认值**: `false`
- **说明**: 是否启用自动提交模式

### AutoCommitInterval
- **类型**: `time.Duration`
- **默认值**: `5 * time.Second`（仅在启用自动提交时生效）
- **说明**: 自动提交的时间间隔
- **建议值**: 
  - 高吞吐场景：3-10秒
  - 低延迟场景：1-3秒
  - 批处理场景：10-60秒

## 🛠️ API 方法说明

### 状态查询方法
```go
// 检查是否启用了自动提交
if consumer.IsAutoCommitEnabled() {
    fmt.Println("使用自动提交模式")
} else {
    fmt.Println("使用手动提交模式")
}

// 获取最后一次自动提交的时间（仅自动提交模式有效）
lastCommitTime := consumer.GetLastAutoCommitTime()
fmt.Printf("最后一次自动提交时间: %v\n", lastCommitTime)
```

### 手动提交方法

#### CommitSync()
批量提交所有已拉取消息的偏移量（传统方式）
```go
err := consumer.CommitSync()
```

#### CommitMessage(msg)
提交单个消息的偏移量
```go
err := consumer.CommitMessage(msg)
```

#### CommitOffsets(offsets)
批量提交指定的偏移量映射
```go
offsets := map[types.PartitionInfo]int64{
    {Topic: "my-topic", Partition: 0}: 123,
    {Topic: "my-topic", Partition: 1}: 456,
}
err := consumer.CommitOffsets(offsets)
```

## ⚠️ 注意事项

### 手动提交模式
1. **必须调用提交**: 忘记调用 `CommitSync()` 会导致消息重复处理
2. **错误处理**: 提交失败时要进行适当的错误处理
3. **性能考虑**: 频繁提交会增加数据库负载

### 自动提交模式
1. **可能重复处理**: 自动提交间隔内的消息可能在故障后被重复处理
2. **不适合事务**: 无法保证消息处理和偏移量提交的原子性
3. **资源清理**: 消费者关闭时会自动执行最后一次提交

## 🔄 模式切换

您可以随时通过修改配置来切换提交模式，但建议在新建消费者时就确定模式，避免运行时切换导致的复杂性。

## 🚀 最佳实践

### 场景选择
1. **金融支付场景**: 使用精确的单消息提交 (`CommitMessage`)，确保每条消息处理成功后才提交
2. **日志分析场景**: 使用自动提交，提高处理效率
3. **批处理场景**: 使用批量指定偏移量提交 (`CommitOffsets`)，减少提交次数
4. **混合场景**: 不同的消费组可以使用不同的提交模式

### 提交策略
1. **高可靠性**: 使用 `CommitMessage()` 逐个提交，确保不丢失数据
2. **高性能**: 使用 `CommitOffsets()` 批量提交，减少数据库交互
3. **条件性提交**: 根据业务逻辑决定是否提交特定消息的偏移量
4. **错误恢复**: 处理失败的消息不提交偏移量，下次重新消费

### 监控和测试
1. **监控**: 定期检查偏移量提交状态和消费延迟
2. **测试**: 在生产环境前充分测试所选的提交模式
3. **日志**: 记录提交失败的情况，便于排查问题
4. **性能**: 根据消息量和处理时间选择合适的提交频率
